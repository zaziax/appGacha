# 0.1.2：安装包手动验收清单

范围：MCP 外部构建、直接入柜、自定义扭蛋目录、应用内弹窗，以及生成／导入／云同步的相关回归。

## 推荐执行顺序

先在 Windows 完整跑一轮，再在 Mac 用该平台安装包复验。每项记录“通过／失败／未测”，开发版通过不等于安装包通过。

| 顺序 | 验收重点 | 完成标准 |
| --- | --- | --- |
| 1 | 安装与旧数据 | 旧扭蛋能打开，记录未丢失 |
| 2 | 目录切换 | 重启生效，新产物只进入选定库，旧库保留 |
| 3 | 目录异常恢复 | 应用仍可进入设置，不偷偷使用默认库 |
| 4 | 外部 MCP | 真正入架、打开可用、重启仍在 |
| 5 | 应用内弹窗 | 样式统一，取消无副作用，Esc 不关闭父设置页 |
| 6 | 内置生成与导入 | BYOK／积分各完成一个可用应用，数据可保存 |
| 7 | 云同步与更新 | 对提供这些功能的安装包完成专项验证 |

最关键的三条是 **数据不丢、MCP 真正入柜、异常时能恢复**。任一失败都先暂停发布。只想先快速冒烟，可先跑 1、2 的迁移主流程、4 的创建入柜、5 的清理草稿；但不能据此跳过完整验收。

## 测试前

- 使用候选版本的 **Windows 与 macOS 实际安装包**，不要只用开发模式验收。记录安装包版本、系统版本、芯片架构和 Git 提交号。
- 测安装包前完全退出开发版，避免单实例转发到旧进程，误以为正在测试新包。
- 用测试账号、测试扭蛋和专用目录。先导出带数据的扭蛋备份；不要拿唯一一份真实数据做故障测试。
- 准备一个能保存内容的小应用，例如记事本：写入“迁移前测试记录 001”，退出再打开确认已保存。
- 准备两个专用目录 A、B，B 为空；至少一个路径包含空格、中文或 emoji。Windows 尽量让 A、B 在不同盘；Mac 有第二个卷时再测跨卷。
- 文中的“重启”指从托盘退出／macOS Cmd+Q 后重新启动，不是关闭主窗口。
- 当前源码版本号为 **0.1.2**。Windows 与 Mac 必须从同一发布提交打包；验证自动更新时使用旧版 0.1.1 作为起点，同版本覆盖安装不能验证“发现新版本”。准备代码不代表 GitHub Release 已发布。
- 可以复用同一个测试记事本／计数器完成保存、迁移、快捷方式、导出与同步测试，不必每项都重新生成。正常 MCP 构建不扣 AppGacha 平台生成积分，但外部智能体自己的模型费用另计。

## 必测一：老用户升级与基本使用（Win / Mac 各一遍）

- [ ] 用候选安装包覆盖旧版安装，启动无白屏、无卡死；原扭蛋仍在，测试记录仍在。
- [ ] 打开、关闭并重新打开测试扭蛋，修改一条记录，完全重启后记录仍然存在。
- [ ] 通过桌面快捷方式打开扭蛋，打开的是目标应用，不额外弹出主窗口；图标正常。（按平台实际支持的快捷方式入口测试。）
- [ ] 主窗口、设置、工作空间切换正常，中英文设置页面均可操作。
- [ ] 有独立测试系统账户时，补测首次安装：无旧配置也能启动、进入设置和创建扭蛋。不要为此删除日常账户的数据。

## 必测二：目录切换（Win / Mac 各一遍）

| 操作 | 预期 |
| --- | --- |
| 设置 → 通用 → 扭蛋存储目录；选择空目录 B，保留“复制” | 显示待重启；当前会话仍使用 A，B 尚未出现半成品扭蛋 |
| 完全退出并重启 | 当前目录变为 B；扭蛋数量、名称及记录 001 一致；A 保留原文件 |
| 在 B 的记事本新增记录 002，再次重启 | B 中记录保留，A 的备份没有跟着更新 |
| 另选一个空测试目录，先点“取消更改”，再重启 | 路径不变，目标目录没有被迁移任务写入 |
| 关闭“复制”，切换到另一份已有测试库 | 只显示目标库的应用；不会合并、覆盖或删除原库 |
| 关闭“复制”，恢复默认目录，再重启 | 使用原默认库；其他目录的内容保留。注意这不是自动合并数据 |
| 保留“复制”并选择非空目录；或选择当前目录的父／子目录 | 明确拒绝，原库和目标文件都不变 |
| 切换后新建、导入和 MCP 各入柜一个扭蛋 | 都存入设置显示的同一目录，重启后仍可见 |

不要在验收结束前删除 A。旧快捷方式的图标如果引用 A，清理 A 前需从新库重新创建快捷方式。

## 必测三：目录故障恢复（只使用测试库）

1. 先切换到专用测试目录并正常使用，然后完全退出。
2. 临时将该测试目录重命名，例如 `B` → `B-offline`，模拟磁盘不可用。**不删除文件**。
3. 启动：主窗口内出现项目风格的目录警告，**不是系统原生警告框**；点“打开设置”进入通用设置，能看到目录错误。点“稍后处理”只关闭警告，不代表恢复成功。不能暗中加载默认库。
4. 尝试创建、需求澄清／获取灵感、导入：应被阻止，不能在默认目录产生新扭蛋，也不应发出模型请求或消费积分。灵感按钮若回退到本地预置内容，不等于调用了 AI。可对照日志／积分余额确认。MCP 不应启动可写的构建服务。
5. 退出，把目录恢复原名，再启动：扭蛋和记录应恢复。
6. 再次模拟不可用，在设置中选另一可用库：复制选项应禁用，重启后加载明确选择的库。完成后恢复测试目录原名，并明确切回后续要测试的库。

- [ ] 上述流程完成，未丢数据、未卡在启动阶段。

配置损坏／路径变成普通文件已由自动化故障测试覆盖。如果要手工复验，只在独立测试系统账户中备份 `egg-storage.json` 后操作：损坏配置后应能进入设置；重新选择目录时原配置保存为 `.recovery-<id>.bak`，重启后恢复。不要故意损坏日常使用的配置、数据库或把真实磁盘填满。

## 必测四：真实外部客户端 MCP（至少一个你实际使用的客户端；Win / Mac）

- [ ] 从安装版设置开启 MCP、创建连接，用它生成的配置接入客户端；无需为了连接单独安装 Node，且不会再启动一个 AppGacha 主窗口。
- [ ] 让客户端创建“可保存计数的计数器”，完成写文件、校验、预览和安装。
- [ ] 工具返回安装成功后，**不需要再次在 AppGacha 点同意**；扭蛋立即出现在架子中，而不只停留在外部构建草稿。
- [ ] 实际打开点几次，关闭重开后计数仍在；完全重启 AppGacha 后仍在架子上。
- [ ] 自定义目录下重复创建，文件确实在新目录；原目录没有新产物。
- [ ] 退出并重开 AppGacha，再让客户端重连，连接可恢复。
- [ ] 撤销该连接后，旧连接无法再写入／安装；新建连接后可正常使用。
- [ ] 关闭 MCP 后，客户端不能继续调用服务；内置扭蛋机仍能正常使用。

可直接发给外部智能体的测试需求：

> 使用 AppGacha MCP 创建一个本地计数器，有加一、减一按钮，关闭后重新打开仍保留数值。先读取宿主规范，完成源码、交互检查和预览，再安装到扭蛋架。等待安装任务返回 installed=true 后才报告成功，不要只创建草稿。

验收时自己点到 3，关闭重开看是否仍为 3。`check_draft` 通过、拿到 job ID、任务结束都不能代替“入柜成功 + 实际可用”。AppGacha 不二次审批入柜，不代表外部客户端不会按自己的规则询问工具授权。

配置中的 token 是密钥，不要贴到截图、Issue 或测试报告中。若客户端缓存连接，关闭旧会话再重连。

## 必测五：弹窗与设置（本次新增重点）

用 MCP 已安装应用留下的草稿副本测试，避免误删尚未交付的唯一草稿。

| 操作 | 预期 |
| --- | --- |
| 设置 → 外部智能体 → 清理草稿 | 出现项目封装的确认框，显示草稿名称及“不会删除已入柜应用”；没有系统确认框 |
| 点取消 | 草稿和已安装应用都保留 |
| 再打开确认框，点遮罩空白处 | 只取消当前确认；设置页仍在，草稿保留 |
| 再打开确认框，按 Esc | 只关闭确认框，不连带关闭设置 |
| 用 Tab／Shift+Tab 切换按钮，等待至少 6 秒 | 焦点留在确认框内；后台状态刷新不抢回焦点 |
| 设置页先滚动到草稿区域，再打开确认框 | 确认框覆盖整窗，不被设置页滚动区域裁切、不躲到设置后面 |
| 点“清理草稿”确认 | 草稿消失；架子上的应用仍在、仍可打开、已保存数据不变 |
| 切到中文／英文分别看上述确认框及目录异常警告 | 标题、按钮随语言变化；长名称／错误信息不撑出窗口，能读到完整内容 |
| 在设置选择目录，或导入／导出文件 | 仍使用系统文件／目录选择器，这是明确保留的行为，不属于失败 |

目录异常警告可和第三部分一起验收，不必反复制造故障。“稍后处理”后目录仍不可用，不能绕过写入保护。

## 必测六：内置构建与导入回归

- [ ] BYOK 创建一个简单的持久化小应用，成功入柜、打开可用、数据可保存。
- [ ] 平台积分模式创建同类小应用，观察成功／失败提示与最终扣费是否一致；不能只看“校验通过”，要实际交互。测试会产生真实模型费用，自行控制预算。
- [ ] 记录两次构建的耗时、是否成功、使用模型，以及积分模式的前后余额。不要求模型输出逐字一致，验收的是功能和交付结果。
- [ ] 对已完成应用做一次小修改，原数据保留，修改生效；中断／续建入口仍正常。
- [ ] 导出一个带数据扭蛋并导入另一测试库，记录仍在；导入同 ID 时冲突提示与“新副本”操作正常。

## 条件必测：云同步与更新

**启用云同步的版本必须测云同步；提供自动更新的正式安装包必须测更新。**没有测试条件时记录“未测”，不要当作通过。

- [ ] 先用测试扭蛋上传一份带已知记录的云端副本，再修改本地；关闭扭蛋窗口后执行云端覆盖，内容应回到预期的云端版本，重启后仍一致。
- [ ] 将测试库放到与应用暂存区不同的盘／卷，重复云端覆盖与“下载为副本”；新副本有独立 ID，原应用不被替换。
- [ ] 打开扭蛋时请求云端覆盖，应提示应用正在使用，不破坏当前数据。
- [ ] 网络断开后下载失败，原应用仍可打开、数据不变。恢复网络后重试成功。
- [ ] 用比旧版更高的真实候选版本，在受控发布环境验证更新提示、更新说明和安装；Windows／Mac 分别验证。不把测试版本提前公开到生产更新源。
- [ ] 更新安装后自定义目录、既有数据和 MCP 连接仍可使用；若安装位置改变导致客户端旧命令失效，重新生成配置并记录这一限制。

磁盘满、备份 rename 失败、发布失败、回滚再次失败等已做自动故障注入。极端情况下如果提示 `Original capsule preserved at`，保留提示所指的 `previous` 目录，停止重试并反馈；它是可恢复的原始副本，不能当缓存删除。

## 已自动化覆盖，不必人为破坏环境复测

- 配置损坏、目录变成文件、复制失败、配置保存失败、回滚失败及原始备份保留。
- 目录不可用时，在构建／澄清／灵感模型请求前拦截。
- 原生确认／警告调用扫描；弹窗确认、取消、Esc、焦点恢复及后台刷新行为。
- 隔离 Electron 内的运行时检查、MCP 完整入柜、实际跨盘文件操作。

这些自动测试减少重复劳动，但不代替上面的系统选择器、安装包、真实客户端、真实模型和实际用户数据保存验收。手动测试不需要把磁盘填满、断电或故意损坏真实数据库。
