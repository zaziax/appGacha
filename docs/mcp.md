# 外部智能体 / MCP（实验功能，0.1.2 起）

AppGacha 是 MCP **Server**：外部智能体编写代码，AppGacha 提供模板、规范、宿主 API、隔离运行检查、预览和入柜。不会转交 fcDriver 再生成，不扣平台生成积分。成品应用运行时的 `egg.ai` 仍走 AppGacha 的 AI 配置，可能产生另外的费用。

## 连接使用

1. 安装并启动 AppGacha 0.1.2 或更新版本。开发者也可构建后启动本地开发版；0.1.1 及更早版本不包含此功能。
2. 设置 → **外部智能体** → **启用本地 MCP**。
3. 给连接命名，创建后复制一次性 JSON 到智能体客户端的 MCP 配置；外层格式可能需要按客户端调整。JSON 含连接密钥，不要公开。
4. 保持 AppGacha 运行。连接器不自动启动应用或开启开关。连接器使用安装时自带的 Electron，设置 `ELECTRON_RUN_AS_NODE=1`；不要求用户另装 Node。
5. 请求智能体读取 AppGacha 的规范、创建并检查应用。授权连接可将验证通过的新应用直接入柜，**无需再切回 AppGacha 确认**。不会自动打开应用，也不覆盖已有应用。客户端自己的工具审批策略仍由用户控制。

示例需求：

> 使用 AppGacha MCP 帮我创建一个能保存训练记录的桌面运动计划应用。先读取 overview 和 api 规范，用宿主能力实现，检查添加训练记录的交互。修复失败检查，不要删除它们。展示预览，然后添加到收藏柜，等待任务返回 installed=true 后再告知我成功。

第一版仅适用于能启动本地 **stdio MCP** 服务的客户端，不支持只能连接远程服务的云端客户端。不会自动编辑第三方客户端配置；不同产品的订阅不一定包含 API 或 MCP 使用能力。

## 工具契约

| 工具 | 用途 |
| --- | --- |
| `get_guide` | `overview`、`api`、`icons` 或 `guides/<topic>`，来自当前宿主随包规范 |
| `create_draft` / `list_drafts` | 创建独立草稿；只列出该连接的草稿 |
| `list_files` / `read_file` | 实时依赖索引、带行号及 SHA-256 的源码读取 |
| `write_file` / `edit_file` | 限定草稿内的文件操作；已有文件要求最新哈希，新文件用 `expected_hash: "new"` |
| `check_draft` | 启动结构、启动和可选交互检查，返回 job ID |
| `get_job` / `cancel_job` | 查询/取消该连接的任务；查询推荐 `wait_ms: 10000`，最多等待 10 秒，减少空轮询；取消不删草稿 |
| `get_preview` | 当前代码版本的隔离测试截图，不是用户桌面截图 |
| `request_install` | 实际交付目录重新验证，通过后直接入柜；返回 job ID 不代表已成功，需等待 `result.installed=true` |

资源 `appgacha://docs/overview`、`appgacha://docs/api` 也提供规范。不支持资源界面的客户端可调用对应工具。

`check_draft` 接收已有运行测试格式（click/fill/wait/assert/assert-change），最多 5 个场景，每个场景必须含断言。已提交场景不能被删除或削弱，可以增加等待和新的检查。内置生成也复用这条限制；真正改变需求时，另建草稿，不把失败义务改成“通过”。

**任务状态 `succeeded` 表示任务执行完毕，不表示应用验证成功。** 检查结果以 `result.ok`、diagnostics 和 coverage 为准。只有启动检查通过不能证明业务可用；真实 AI、外部联网、系统对话框及长期运行均不在模拟检查保证范围内。

## 安全及数据边界

- 默认关闭。每个连接独立随机 256 位密钥，宿主只保存哈希，原密钥仅在创建时显示一次。丢失需撤销后重建。
- 撤销后禁止后续访问并取消该连接正在执行的任务；草稿保留供用户清理，不转交其他连接。关闭 MCP 停止桥接和任务，但保留连接记录供主动重新开启。
- 源码、诊断和预览可能进入外部模型服务商。这是用户主动连接功能，与匿名统计开关无关；不会因此自动上传至 AppGacha API，也不扩充现有遥测。
- 不开放已有应用列表、真实用户数据、API 密钥、账号令牌、任意命令、任意路径、远程执行、删除工具或云端分享。
- 宿主文件和私有数据受保护。单文件写入最多 500KB，源码总计最多 5MB / 128 文件；每连接最多 8 个未入柜草稿，全局 24 个；最多 8 个连接。
- 检查和安装期间锁定草稿；验证后改文件会失效。安装在目标扭蛋架目录中创建无 `.gacha` 后缀的临时候选目录，复制草稿并裁剪资源后独立复验，比较源码及候选目录指纹，再同盘重命名和注册。支持草稿与扭蛋架位于不同磁盘/卷；不会跨盘 rename。只新增，不覆盖、不自动打开应用。
- MCP 检查/安装与内置构建共用互斥状态，更新器不会在其间重启。单纯编辑另一个外部草稿不阻塞内置生成。
- 检查使用与内置生成相同的隔离数据、模拟 AI 和外部副作用限制，不把测试数据复制进成品。验证通过并不等于生成代码绝对安全，运行期能力沙箱仍是必要防线。
- 私有桥接仅绑定 `127.0.0.1`，校验 Host、拒绝所有浏览器 Origin、要求令牌、限制请求大小/频率，只接受固定工具。它**不是 Streamable HTTP MCP 端点**，请使用 stdio 连接器，不要通过代理或隧道暴露。
- 这不能隔离已经以同一操作系统用户身份运行的恶意本地进程。文件在支持的平台使用私有权限；Windows 依赖用户 profile 的 ACL。

## 存储与恢复

`<userData>/mcp/` 下存储 `connections.json`（开关及密钥哈希）、`endpoint.json`（当前回环端口，不含令牌）、`drafts/<id>/`（源码、元数据、预览）。连接配置不含用户的模型或账号密钥。元数据保存最近任务状态及错误，在设置中显示；完整任务与验证凭据不跨重启保留。

默认开发版扭蛋架位于 `<appPath>/eggs`，安装版位于 `<userData>/eggs`；设置 → 通用中可[自定义扭蛋目录](egg-storage.md)，下次启动生效，MCP 入柜自动跟随。安装临时目录为扭蛋架下的 `.mcp-install-*`，未完成目录不会被当作应用加载。正常失败会清理该次临时目录，源草稿始终保留；进程崩溃或文件占用导致清理失败时可能残留临时目录，但不会误上架。

草稿跨重启保留；任务状态和验证凭据不跨重启信任。用相同连接重连后 `list_drafts`，再检查一次。新建连接不会继承旧连接草稿。

设置里可以确认后永久清理草稿，包括已入柜应用的草稿副本；不影响收藏柜内成品。移动安装目录后需重新复制配置。正常原位升级保留用户数据位置和授权，连接器每次请求读取新端口。

关闭外部客户端不自动取消后台任务，请使用 cancel_job、撤销连接或关闭 MCP。取消已成功提交的安装不会回滚。重启后未完成的历史任务显示为中断；同一连接可以重新检查并重试。

## Codex 等外部客户端的职责

MCP 不接管客户端的推理、计划、模型或沙箱。客户端自行决定如何调用工具，AppGacha 提供草稿文件、规则、检查和入柜服务，不转交 fcDriver，也不能控制客户端是否询问工具授权。

连接器在 MCP 初始化 `instructions` 中提供跨工具流程，工具同时返回文本与 `structuredContent`，便于不同客户端消费。长任务使用 job ID 和有界等待，避免一次工具调用等待整个构建过程。规范按主题读取；截图单独请求，避免每次文件操作都返回大量规范或图片。

Codex 使用 TOML 而不是直接粘贴 `mcpServers` JSON。将一次性配置中的 command、args、env 对应填入：

```toml
[mcp_servers.appgacha]
command = "<复制 command；路径中的反斜杠需转义，或使用正斜杠>"
args = ["<复制 args 中的连接器路径>"]

[mcp_servers.appgacha.env]
ELECTRON_RUN_AS_NODE = "1"
APPGACHA_MCP_ENDPOINT_FILE = "<复制 endpoint 路径>"
APPGACHA_MCP_TOKEN = "<复制一次性连接密钥>"
```

配置方式、工具超时及审批策略参考 [Codex 官方 MCP 文档](https://developers.openai.com/codex/mcp/)。不自动写入或降低客户端的审批设置。

## 验证与发版边界

```text
npm run typecheck
npm test
npm run test:runtime
npm run test:mcp
npm run build
```

单元测试覆盖授权、隔离、过期哈希、场景保留、取消/撤销、直接入柜、代码指纹、失败保留与重试、同名保护、短暂文件占用重试、状态恢复、原生连接边界及真实 SDK stdio 握手和有界等待。

`test:mcp` 使用独立 Electron profile，通过真实 MCP 写入持久化计数器，执行真实隔离交互检查、取回截图、最终复验、直接注册入柜。不需要确认桩。草稿位于系统临时目录，目标扭蛋架位于仓库的独立临时目录，在 C 盘临时目录 / E 盘仓库环境中覆盖真实跨盘入柜。不访问实际用户应用、不调用真实模型。

公开发布前还需在两个目标客户端、Windows/macOS **安装包**上手工测试：设置复制配置、直接入柜/取消/撤销、移位安装、应用升级后重连。开发态测试不代表这些已完成。版本号、发布说明、签名/公证是独立发版工作，本实现不自动发布。
