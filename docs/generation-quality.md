# 生成与修复质量：第一轮落地

本轮保留自研 fcDriver 和现有宿主 API。目标是减少“模型改了文件却没有修到实际执行路径”“窗口打开就误报成功”“异常后重复付费从头生成”等问题，不是替换 Agent SDK 或保证任意需求均可完成。

## 当前链路

1. **需求**：机器页传递完整问题和对应答案，忽略空白和交给 AI 决定的答案，不再只拼接失去语境的回答。
2. **上下文**：生成与修复使用共同规则；每轮刷新实际文件索引、导入关系、导出及诊断，旧 `EGGDOC.md` 只作参考。
3. **计划与操作**：写文件前记录短计划、涉及文件和预期结果；支持有行号的分段读取、字面搜索、唯一匹配编辑及内容哈希校验。工作区工具拒绝越界、私有数据、符号链接及受保护宿主资源写入。
4. **结构检查**：通过 JavaScript AST 和 HTML/CSS 资源引用检查缺失模块、路径大小写、错误导出等；动态依赖无法确定时保守保留并给出警告。
5. **运行检查**：使用独立目录、独立 Electron session 和测试身份，在生成页面运行前挂载资源与异常监测。捕获加载失败、CSP、同步/异步初始化异常、崩溃等。
6. **交互检查**：模型可以提交有明确断言的 click/fill/wait/assert 场景。仅点击不算验证；场景需要观察文本或输入值的结果。修改已提交场景需要说明原因。
7. **修复闭环**：修复前先检查基线，将实际诊断交回模型。重复出现相同失败时暂停；保留草稿、协议完整的对话和场景定义。
8. **最终产物**：根据依赖图裁剪资源后重新验证实际交付目录，验证通过才入柜或替换旧代码。断点在提交成功后清理。

## 用户看到的变化

- 不增加开发术语表单或强制用户编写测试。
- 成功卡明确区分“启动检查通过”和“已通过 N 项本地交互检查”，不宣称全功能正确。
- 中断后可以继续当前草稿；界面提醒续建仍会使用当前 AI 通道并产生用量。
- 本轮没有修改套餐、赠送积分、上游收费或遥测政策。

## 成本与取消边界

- HTTP 429 最多请求 3 次。明确的 `finish_reason: length` 不执行该轮任何工具，但可以调整分块策略、在任务预算内自动恢复最多 3 次；网络中断、缺少完成标记、余额不足及其他错误不盲目重放。
- 生成默认显式申请 16,384 输出 tokens，首次可恢复截断后最多提高到 32,768。若代理报告实际额度更低，则保持原申请并缩小操作。计入失败响应的用量，沿用 60 轮、15 分钟和单次运行累计输出 300,000 tokens 护栏；这个输出护栏不是人民币预算或输入输出总量限制。
- 恢复次数与当前输出额度保存在断点里，不因重启自动清零。用户主动续建仍会获得新的运行时长/轮数/输出预算窗口，但不会重置累计自动截断恢复次数。
- 代理按 `purpose=app_build` 区分生成与问答；普通问答仍默认 4,096 / 最高 8,192。生成在用户事务锁内按余额协商可覆盖的输出额度，默认最低 4,096（请求更少时不强行抬高），预占与上游实际限制一致；最低额度也无法覆盖时仍返回 402。套餐和积分单价没有改变。
- 代理通过 `X-AppGacha-Output-Limit` 报告实际允许的额度，并在正常流中先结算退回未用预占，再发送 `[DONE]`。客户端收到 length 后额外等待最多 5 秒收集尾部 usage，不把失败视为免费；缺失 usage 时只对本地输出护栏做保守估算，真实扣费仍由服务端结算。
- 本地日志记录请求/代理额度、结束原因、正文/推理/工具参数字符数和上游 usage，不记录完整推理或代码。字符数不是精确 token 分类；没有上游 usage 时不能声称已知真实用量。
- 调用方取消信号覆盖请求、流读取、检查和提交前的文件锁等待。已经成功完成的本地提交不反向撤销。
- 已被上游接受的请求可能已经计费；客户端取消不代表上游退款。
- 上下文压缩按完整工具调用组处理，保存中断时给未完成的工具调用补上中断结果，不留下孤立的 tool 消息。

## 测试隔离与证据边界

- 检查读取代码和测试数据副本；交互产生的数据不写回源扭蛋。
- AI 能力使用本地 mock，网络房间功能不连接真实服务；文件选择/保存不会弹出真实系统对话框，通知和计划任务没有真实外部副作用。
- 因此通过检查**不代表真实 AI 响应、联网、系统文件对话框、长期计时、重启后恢复或全部业务需求已被验证**。
- `build-report.json` 保存验证时间、级别和场景数量，不保存源码、输入数据或完整诊断；标明外部服务未验证。
- 升级时对旧数据副本的检查目前是启动检查，不能当成完整的数据迁移或旧数据业务回归。
- 由生成模型编写的断言仍可能不充分。后续需要独立固定用例集和人工体验确认，不能用自检替代成功率评估。

## 本地验证

在仓库根目录执行：

```text
npm run typecheck
npm test
npm run test:runtime
npm run build
```

`test:runtime` 使用专用测试入口和临时 profile，不启动正式 `index.ts`，不调用真实模型、不使用用户扭蛋数据。它需要可运行 Electron 的图形环境；受限沙箱或缺少系统库时应在具备条件的本机环境运行，不应将环境故障当成应用回归。

回归覆盖包含：丢失模块仍有静态页面、初始化/异步异常、CSP、按钮无绑定、协议截断、取消、断点续建、场景保持、最终验证和资源裁剪。

## 发布前仍需补的验证

1. 固定若干真实需求，以相同模型配置比较首轮完成率、修复成功率、总 token 和耗时；这需要明确的模型调用预算。
2. Windows / macOS 正式安装包手动回归快捷方式、窗口、扭蛋持久化与升级。
3. 对外部 AI、联网、文件导入导出和旧数据迁移设计专门的受控集成用例。
4. 本轮不修改原始 Focus Timer 样本，不据此宣称它已修复，也不自动发布新版本。

## 输出预算修订的部署顺序

先更新 API 服务，再重新构建和分发桌面端。无需数据库迁移；只是复用预占记录的 `output_tokens_reserved` 字段。老客户端不发送用途标记，仍使用原问答额度；新客户端连接老服务仍可能被压到 8,192，不能只发布客户端就宣称问题已修复。

16K / 32K 是本轮的工程起点，不是所有 BYOK 模型的能力保证。发布前需确认实际模型/网关接受该额度，并用固定真实任务验证首轮成功率、自动恢复成功率和费用。明确的模型参数拒绝不会被当成截断无限重试。

## 2026-09-15：执行节奏与可解释性

- 局部编辑展示的是被替换片段的行数 → 新片段行数，包含作为定位上下文的行，不是净增删行数。不再将所有 edit_file 固定显示为 1 行。
- 提示词鼓励同一逻辑目标的安全小操作成组完成、再验收；有返回值依赖的操作不能为减少轮次而盲目合并。16K 输出请求与 60 轮硬上限不变。
- 使用 45 轮、11 分钟或 225K 累计输出之一触发收尾提示，后续每轮都保留在实时任务提示中，UI 只提醒一次。优先补齐原始核心需求和回归，不增加非必要润色；不自动删需求、降低断言或宣布成功。硬上限仍保持断点保存行为。
- 显式 check_egg 总是重新运行。只有 finish 能复用同一次驱动运行中、不超过 30 秒的成功检查；比较所有文件内容（含 data、vendor）、目录、场景定义及进程平台/版本。仅排除根目录宿主检查点、检查截图与构建报告；遇到符号链接、读取失败或超过扫描预算时不复用。失败结果不缓存，恢复任务不继承缓存，清理后最终产物独立复验不变。
- 本地日志新增 `[fc] tool completed`（回合、工具、合法相对路径、片段行数、耗时、错误类别）与 `[fc] check completed`（通过/失败/复用、文件及场景指纹、检查类别、失败步骤、诊断类别）。不写工具参数、源码、密钥、断言值、观察值、测试输入或场景名称；哈希用于关联问题而不是暴露原始内容。现有其他日志并不因此自动获得脱敏保证。
- `build-report.json` 增加场景序号、定义哈希与各步骤动作/结果；不记录测试内容。结构化日志和报告仍为本地产物，不新增遥测或自动上传行为。它们能定位第几个场景在哪一步失败，但不等于独立业务正确性证明。
- 真正压缩重复上下文、判断测试是否覆盖充分，仍需用新日志和固定任务集评估；本轮不按轮次宣称成功率或成本已改善。

## 等待体验：统一时间线（按体验反馈调整）

- 思考说明、文件读取/写入/修改、自检和修复按原始顺序混排在同一时间线，不再分出「构建详情」。文件操作只显示路径，不在界面展示片段行数；完整行数仍保存在诊断日志中。顶部保留真实阶段与耗时，不将内部上限作为完成百分比。
- 最新一条模型普通 content / set_plan 过程说明默认展开，下一条说明出现时自动折叠旧说明；可手动展开历史内容。文字按真实接收内容显示，取消人为延迟打字效果。
- 提示词要求模型在关键阶段用普通 content 提供一句面向用户的简短说明，与工具调用同轮，不为说明额外请求模型，不要求暴露内部推理。模型未遵循时依靠真实事件状态反馈，不能保证每轮有自然语言说明。
- 按最新体验选择，界面只显示普通 content 和简短方案，与构建步骤混排；reasoning_content 不接入界面，也不写入新增诊断日志。底层仍保留模型协议要求的推理历史与用量统计，不关闭模型思考能力。
- 收到真实推理/工具 delta 时最多每秒刷新一次阶段状态；普通 content 按收到的片段持续追加。SSE keep-alive 和本地计时器不会模拟模型输出。
- 已用时持续更新；20 秒没有进展事件时在顶部显示紧凑等待提示及无新消息时长，不另外占用时间线卡片，不继续断言模型在思考或代码已完成。收到新事件立即恢复实际状态。
- 本轮不改变模型预算、计费、自检标准，也不处理失败场景被移除的问题；后者需独立核对需求与场景定义，不能靠界面美化掩盖。
