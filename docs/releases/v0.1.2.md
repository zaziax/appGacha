## English

AppGacha 0.1.2 adds a new way to build capsules with your own AI agent, more control over local storage, and improvements to generation, verification and recovery.

### What's new

- **Local MCP support (experimental).** Connect a local stdio-capable agent to create, check and preview new capsules. Once verified, authorized connections can install them directly to the shelf—no extra per-app confirmation in AppGacha. Enable it in **Settings → External agents**; it is off by default.
- **Choose your capsule directory.** Store your apps and their data in a dedicated folder or on another drive. Changes take effect after fully quitting and restarting. You can copy existing capsules while keeping the original library as a backup.
- **Improved generation and repair.** Refreshed project context, targeted file editing, isolated runtime and interaction checks, resumable progress, and final artifact verification. Previously submitted regression checks cannot be removed or weakened to bypass failures.
- **Clearer progress.** Build explanations and file operations appear together in one timeline, with elapsed time and waiting feedback.
- **Safer storage and cloud replacement.** Cross-volume cloud replacement protects original capsules when copying or replacement fails. A damaged storage configuration or unavailable directory leaves Settings accessible, without silently switching libraries. Build-related AI requests are blocked while storage is unavailable.
- **Consistent in-app dialogs.** Draft cleanup confirmations and directory warnings use AppGacha's own interface, with better focus handling and Escape behavior. System file and folder pickers remain available.

### Before using MCP

Keep AppGacha running. MCP exposes connection-owned drafts, not existing apps, user data or your AppGacha API keys. Source code, diagnostics and previews may be sent to your external agent's provider. External generation does not consume AppGacha platform credits; your agent provider may charge separately, and AI calls made by a running capsule still use your AppGacha AI configuration.

Local checks do not guarantee every business workflow or external service works. Open the generated app and try its key actions before relying on it. Resuming an internal build can incur further model usage.

Available for **Windows x64** and **macOS Apple Silicon**. Before moving your library, back up important data. If a storage error reports a preserved original capsule path, keep that backup for recovery.

## 中文

AppGacha 0.1.2 新增使用外部智能体构建扭蛋的方式，支持自定义本地存储目录，并改进生成、验证与异常恢复。

### 更新内容

- **本地 MCP（实验功能）。** 连接支持本地 stdio 的智能体，创建、检查和预览新扭蛋。验证通过后，授权连接可直接入柜，无需在 AppGacha 中逐个确认。在 **设置 → 外部智能体** 中开启，默认关闭。
- **自定义扭蛋目录。** 将应用和数据存放到专用文件夹或其他磁盘。完整退出并重启后生效，可复制已有扭蛋，同时保留原库作为备份。
- **改进生成与修复。** 刷新项目上下文、精准编辑文件、隔离运行与交互检查、保留可续建进度，并验证最终交付产物。已经提交的回归检查不能通过删除或削弱来绕过失败。
- **更清晰的构建进度。** 过程说明与文件操作统一展示在时间线中，显示已用时间与等待状态。
- **加强存储和云端替换保护。** 跨盘云同步在复制或替换失败时保护原扭蛋。配置损坏或目录不可用时仍可进入设置，不静默切换到默认库；恢复前阻止构建相关 AI 请求。
- **统一应用内弹窗。** 草稿清理确认与目录警告采用 AppGacha 自身界面，改善焦点与 Esc 行为；系统文件和目录选择器继续保留。

### MCP 使用说明

请保持 AppGacha 运行。MCP 仅开放当前连接创建的草稿，不开放已有应用、用户数据或 AppGacha 中配置的 API 密钥。源码、诊断与预览可能发送给外部智能体服务商。外部生成不扣 AppGacha 平台积分，但外部智能体可能单独收费；成品运行时的 AI 调用仍使用 AppGacha 的 AI 配置。

本地检查不保证全部业务流程及外部服务正确，请实际打开应用并测试关键操作。内置构建的断点续建仍可能产生新的模型用量。

支持 **Windows x64** 与 **macOS Apple Silicon**。迁移目录前请备份重要数据；若存储错误提示了原始扭蛋的保留路径，请保留该副本用于恢复。
