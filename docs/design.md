# appGacha 设计总览与决策记录

> 状态：M1-M3 已实现 · 最后更新 2026-07-19

## 1. 问题与定位

**痛点**：对小白来说，难的从来不是"让 AI 写出代码"，而是代码之后的一切——运行环境、数据持久化、Node/端口等概念、迁移分发。AI 生成能力已经商品化，但"生成物的运行时"没有人给小白解决。

**定位**：appGacha 把"生成 + 持久运行时 + 可迁移"打包成一个傻瓜盒子。用户填写愿望单（例如"我想要一个背单词软件"），后台智能体按严格规范扭出插件（扭蛋 `.egg`），扭蛋在主应用提供的沙箱中运行，拥有自己的数据库和文件空间，整个文件夹可拷贝迁移。

**差异化**：三者的交集，砍掉任何一个都掉回已有产品的领域。

- uTools/Rubick：有插件运行时，无 AI 生成
- Claude Artifacts：有 AI 生成，无持久化与本地能力
- appGacha：生成 + 持久运行时 + 可迁移，且蛋**天生 AI**（见决策 D4）

**扭蛋隐喻的价值**：天然设定"结果有随机性、不满意可以再抽"的心理预期，为生成不完美兜底。

## 2. 系统分解

```
┌─ appGacha 主应用 (Electron) ─────────────────┐
│                                              │
│  ① 收藏柜 UI      愿望单 / 扭蛋中 / 我的收藏   │
│  ② 蛋运行时       webview + preload bridge    │
│  ③ 能力层         ai/db/storage/fs/notify/... │
│  ④ 蛋管理器       安装·加载·备份·导入导出      │

      .egg 格式规范（docs/egg-spec.md，全系统的契约锚点）
```

## 3. 核心决策记录

### D1 沙箱 + 能力桥接，不给蛋真实 Node 环境

沙箱不是安全选项，而是产品本身：

1. **沙箱是"可迁移"承诺的前提**。真实 Node 环境意味着 node_modules、native 依赖、版本要求——换台机器就把"环境问题"这个原始痛点还给用户。纯 HTML/JS + bridge 的蛋才是 copy 即运行。
2. **沙箱是生成成功率的前提**。封闭的目标 API 可以在系统提示里穷举、可以自动校验；"可以 require 任何包"是不可校验的世界。
3. **能力不够时，扩展主应用而不是打开沙箱**。每个新能力都是审核过、文档化、智能体可靠掌握的 bridge API（uTools 验证过的路线）。

例外场景（后台常驻逻辑）用"主应用代跑"解决：manifest 声明 `schedule`，主应用调度执行蛋提供的受限 JS，蛋不自己起进程。

### D2 生成管线基于 Claude Agent SDK，工程收窄（已被 D2' 取代）

复用现有优秀智能体产品，不自建 agent loop。工程控制点：

- **收窄工具面**：智能体只有对蛋文件夹的读写、`validate_egg`（manifest schema 校验 + 静态检查是否越出 bridge API）、`test_egg`（无头 Electron 运行、截图、收集 console 报错）。
- **脚手架优先于自由生成**：提供蛋模板（manifest 骨架、`egg.d.ts` 类型声明、示例代码），让智能体做填空题。类型声明是把 API 规范喂给智能体的最佳载体。
- **验收闭环在管线内，不在用户面前**：生成 → validate → 无头运行 → 截图自查 → 不合格自动迭代（上限 3 轮），超限才抛"这次没扭出好蛋，再来一发？"。
- 小白不会调试，出蛋质量闭环是"小白可用"承诺兑现的关键。

### D2' 修订：自研微型机芯（自建 function calling 循环），Agent SDK 出局

**变更原因**：Agent SDK（`@anthropic-ai/claude-agent-sdk`）在运行期依赖本机 Node/CLI 环境，与产品硬约束冲突——**一切能力都必须由应用扭蛋机本身提供**，用户机器上不能预设任何运行时。Electron 自带的 Node 只服务于主进程，无法拉起 SDK 需要的独立子进程链。

**替代方案**：主进程内自建 function calling 循环（`src/main/fcDriver.ts`），走 OpenAI 兼容 `/chat/completions` 的 tools 协议：

- 工具面只有 5 个：`list_files` / `read_file` / `write_file` / `check_egg` / `finish`，全部只作用于装配舱目录。
- 系统提示内嵌 `EGG_GUIDE.md` + `egg.d.ts`——D2 的"脚手架优先"原则原样保留，智能体做填空题。
- 预算护栏：60 回合 / 300k tokens / 15 分钟，超限即失败归档。

**质量风险的对冲**（自建 loop 不如成熟智能体聪明，用工程弥补）：

1. **验收闸门独立于驱动**：`validate_egg`（静态检查）+ `test_egg`（离屏运行、截图、console 收集）在管线内强制执行，最多 3 轮修复循环——驱动再笨也过不了假货。
2. **驱动可插拔**：管线定义 `GachaDriver` 接口，fcDriver 只是当前实现；未来若出现可内嵌的成熟智能体（或自研驱动质量见顶），换驱动不动管线。
3. **金标愿望集**（待建）：约 10 条标准愿望作为回归基准，量化出蛋率，驱动/提示词改动有据可依。

**保护性复写**：manifest 的 `eggId` / `wish` / `hostApiVersion` / `createdBy` 由管线在出蛋前强制复写，智能体篡改无效。

D2 中的工具收窄、脚手架、管线内验收闭环三原则全部继承，仅"复用现有智能体"一条作废。

### D3 模型接入双轨制

机芯与蛋的 AI 能力统一走 **OpenAI 兼容接口**（`/chat/completions`），DeepSeek / Kimi / Qwen 等均可直配 base URL + model + key。

- **MVP**：用户自配 API（key + base URL），key 经 safeStorage（Windows DPAPI）加密存储在本机。
- **商业化阶段**：默认托管（如 DeepSeek 转售，按百分比浮动加价作为利润）。托管顺便解决小白配置门槛，且蛋的运行期 AI 调用（见 D4）让利润来自蛋的整个生命周期而非扭出那一次。
- 托管牵扯账号、支付、防滥用，是另一个量级的工程，MVP 不做。

### D4 蛋天生 AI（`egg.ai`）

主应用手里已握着模型通道，`egg.ai` 把通道桥接给蛋——蛋不需要 key、不需要 SDK。这是市面上没有的东西：小白许愿得到的不是"死"程序，而是自带智能的活物。

| 愿望 | 无 AI 的蛋 | 天生 AI 的蛋 |
|---|---|---|
| 背单词 | 卡片翻转 | 自动生成例句/助记/近义词辨析 |
| 记账本 | 手填表单 | 粘贴"昨天买菜38"自动结构化入账 |
| 日记本 | 文本框 | 每周自动生成情绪回顾 |
| 作文练习 | 存文档 | 内置批改和润色 |
| 课程表 | 手动录入 | 粘贴课表文本自动解析 |

接口形态与约束见 egg-spec。

### D5 蛋的进化 = 外部"许愿升级"，仪式感优先

蛋不做内部自迭代。进化入口在主应用层面：收藏柜里每个蛋有"许愿升级"按钮，用户对着蛋许愿（"加个夜间模式"），扭蛋机芯拿 manifest 中留存的原始 `wish` + 现有代码做增量进化。

**理由**：外部许愿保持了扭蛋的仪式感——升级也是一次"抽"，与产品隐喻一致；同时进化逻辑集中在扭蛋机芯，蛋保持纯粹的运行物。

配套约束：**每次升级前自动整蛋备份**（数据 schema 迁移是最容易丢数据、最伤信任的环节）。

### D6 v1 能力清单的划线标尺

不追求 API 面最小，而是：**把杀手级愿望单 Top 10 摊开，缺了会让蛋从"惊艳"掉到"玩具"的能力就进 v1。** 结论：提醒类愿望（背单词提醒、番茄钟）是小白需求重灾区，`notify` + `schedule` 必须进 v1；具体清单见 egg-spec。v1 约 8 个能力域，仍是智能体一份文档能吃透的规模。

## 4. 路线图（设计→实现顺序）

1. **`.egg` 规范 + bridge API v1**（已定稿，见 docs/egg-spec.md）✅
2. **蛋运行时**：webview 隔离、preload 注入、权限拦截 ✅ M1
3. **能力层补齐 + 收藏柜（素颜版）**：egg.ai / notify / schedule / fs / window，模型设置 ✅ M2
4. **扭蛋机芯**：自研 FC 循环、蛋模板、验收闭环、许愿进度流 ✅ M3
5. **许愿升级（M3.5）**：备份 → 增量进化 → 迁移验收（待做）
6. **收藏柜化妆（M4）**：视觉与动效打磨（待做）

模型托管计费推迟至商业化阶段。

## 5. 术语表（产品语言）

产品隐喻是**扭蛋机**：机器制造胶囊，蛋是产物——生成逻辑全在机芯、蛋只是运行物，与架构（D5）一字不差。禁用孵化/破壳/巢等"母鸡视角"词汇（孵化暗示蛋自己长大，恰是被否决的内部自迭代）。

| 术语 | 含义 | UI 文案基调 |
|---|---|---|
| 扭蛋机芯 | 生成管线（自研 FC 循环 + 验收闭环） | 用户不可见的机器内部 |
| 装配舱 | 生成期的隔离工作目录 staging | 用户不可见 |
| 投币 → 旋钮转动 → 机芯咔咔 → 咔哒！ | 管线四阶段事件 | 扭蛋动画的进度文案 |
| 出蛋 | 验收通过，移入收藏柜 | "咔哒！你的蛋出来了" |
| 收藏柜 | 用户的蛋列表（原"蛋架"） | 收藏陈列感 |
| 再来一发 | 生成失败后重试 | "这次没扭出好蛋，再来一发？" |
| 许愿升级 | 对着收藏柜里的蛋再许愿（外部进化，D5） | 仪式感入口 |
